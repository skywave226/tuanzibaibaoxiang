# 新工具提案模板

扩充每类工具时，一张提案对应一个独立的用户任务。先在[工具清单](tool-catalog.md)中搜索同名和近似功能，并按[分类规则](../scripts/category-taxonomy.json)选择唯一主分类。新增工具后运行 `npm run catalog:generate` 和 `npm run catalog:check`。

## 提案

- 工具名称及唯一地址：
- 主分类及归类依据：
- 用户要完成的具体任务：
- 输入（格式、示例、大小或数量限制）：
- 输出（格式、示例、复制或下载方式）：
- 与现有最相似工具的差异（附地址）：
- 错误、空输入和不支持格式的处理：
- 浏览器能力、外部服务及隐私要求：
- 至少两个验收场景（含预期结果）：

仅更换标题、预设值或界面样式，若输入与输出能力没有实际区别，应扩充现有工具，不计为新工具。

## 已发现的功能重叠

| 工具地址 | 当前判断 | 后续处理 |
| --- | --- | --- |
| `/english-grammar`、`/grammar-reference` | 都提供英语语法资料；后者范围更广 | 现阶段以“基础”和“速查”区分名称；扩充前评估是否合并内容。 |
| `/sql-formatter`、`/sql-formatter-db` | 都格式化 SQL；后者支持多方言 | 保留快速入口和多方言入口，避免仅改变方言预设来增加工具数。 |
| `/unit-converter`、`/unit-converter-edu` | 都换算单位；前者覆盖更多单位 | 保留完整与基础入口，扩充前评估是否合并。 |
| `/color-picker-game`、`/game-color-picker` | 颜色转换和调色板功能高度重叠 | 保留现有地址；后续核对独有功能及使用量，再决定合并。 |
| `/pixel-art-editor`、`/pixel-art-tool` | 像素画绘制、调色板和导出功能高度重叠 | 保留现有地址；后续核对独有功能及使用量，再决定合并。 |

合并现有工具时，应先确定功能保留方案和旧地址的跳转或兼容方式，不直接删除入口。
