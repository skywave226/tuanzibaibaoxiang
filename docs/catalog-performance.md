# 工具目录扩容基线

测量日期：2026-10-19。当前有 180 个工具、25 个分类、1,980 个多语言工具页面。下表中的构建都在同一台 Windows 开发机上执行 `npm run build`；文件大小取构建日志的入口 JS 产物，gzip 是构建工具的估算值。构建时间会受机器负载影响，只适合作为后续扩容的参考。

| 指标 | 改造前 | 改造后 |
| --- | ---: | ---: |
| 首页初始入口 JS | 1,355.02 kB | 863.30 kB |
| 首页初始入口 JS gzip | 368.98 kB | 251.11 kB |
| 首页一次渲染的工具卡片 | 180 | 最多 48 |
| Vite 构建阶段 | 34.08 秒 | 30.53 秒 |
| 站点产物总大小 | 21,054,230 字节 | 20,969,343 字节 |
| 生成的多语言工具页面 | 1,980 | 1,980 |

首页现在使用精简的中文工具索引；切换语言时才加载该语言的工具译文。工具图标按分类拆分，页面只请求当前可见分类对应的图标文件。搜索和分类筛选仍针对完整工具集执行，再对结果分页，因此每页展示上限不会限制查找范围。

扩到 500、1,000 和 2,000 个工具时，分别重新记录入口 JS 大小、目录页渲染卡片数、构建时间、产物总大小和实际部署时间；同时运行 `npm run catalog:check`、`npm run build`、`npm run test:catalog-ui`。超过当前基线时，应先定位增长来自索引、译文、图标还是静态 SEO 页面，再调整发布策略。
